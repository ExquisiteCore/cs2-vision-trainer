# 当前用户文档中文化设计

## 目标

将项目当前面向使用者的说明文档统一改为简体中文，使中文使用者能够完成项目拉取、构建、模型训练、运行时使用、固件构建和板控 SDK 集成，而无需阅读英文说明。

## 翻译范围

本次只处理当前用户文档，共 8 份：

1. 父仓 `README.md`
2. 父仓 `docs/BUILD.md`
3. 父仓 `docs/USAGE.md`
4. C++ runtime 仓库 `README.md`
5. C++ 板控 SDK 仓库 `README.md`
6. 固件仓库 `README.md`
7. Python 板控 SDK 仓库 `README.md`
8. C++ runtime 仓库 `packaging/sm61/package/README_中文.md`

`README_中文.md` 已以中文为主，本次只检查遗漏的英文说明、术语一致性和内容时效性。

## 不在范围内

- `docs/superpowers/plans` 下的历史实施计划
- `docs/superpowers/specs` 下除本文外的历史设计记录
- 源代码注释、测试名称和日志字符串
- `LICENSE`、第三方许可证和依赖说明
- 命令行输出、协议常量、API 名称、类名、函数名、配置键和文件名
- 构建目录、发布产物和自动生成文件

## 翻译规则

### 正文

- 标题、段落、表格标题、提示、警告和故障排查说明使用简体中文。
- 保留必要的行业术语；首次出现时可使用“中文名称（英文缩写）”，后续使用约定术语。
- 不逐字直译，以准确表达当前代码行为和使用流程为准。

### 不翻译内容

- Markdown 代码块和行内代码中的命令、路径、参数、环境变量和标识符。
- URL、Git 仓库地址、提交哈希和硬件型号。
- 协议字段与常量，例如 `PROTOCOL_VERSION`、`STOP_ALL`、`NO_RESPONSE`。
- 用户需要原样复制执行的终端命令。

代码块中的纯英文注释或占位说明可以翻译，但不得改变命令语义。

### 统一术语

| 英文 | 统一中文表达 |
|---|---|
| runtime | 运行时 |
| firmware | 固件 |
| host | 主机 |
| bridge | 桥接器 |
| SDK | SDK |
| payload | 载荷 |
| heartbeat | 心跳 |
| batch | 批处理 |
| dry run | 试运行 |
| portable package | 便携包 |
| model schema | 模型结构说明 |
| submodule | 子模块 |

## 仓库处理顺序

翻译按依赖关系从内到外进行：

1. C++ 板控 SDK
2. Python 板控 SDK
3. C++ runtime
4. 固件仓库，并更新内部 SDK 子模块引用
5. 父仓，并更新所有相关子模块引用

每个仓库只提交属于自己的文档变化。相同的 C++ SDK 提交同时用于父仓一级 SDK 和固件仓内 `sdk/cpp`，避免出现两个版本。

## 验证

翻译完成后执行以下检查：

1. 确认 8 份目标文档的标题和说明正文已中文化。
2. 扫描残留英文段落，区分允许保留的代码、命令、标识符和专有名词。
3. 检查 Markdown 围栏代码块成对闭合。
4. 检查相对链接指向的本地文件仍然存在。
5. 对包含可执行命令的仓库运行原有测试和构建验证，确认文档修改没有意外影响文件结构。
6. 检查所有仓库工作区和递归子模块状态。

## 完成标准

- 8 份目标文档的用户说明正文均为简体中文。
- 所有复制执行内容保持原有语义。
- 历史计划和设计文档保持不变。
- 两份 C++ SDK 仍指向同一提交。
- 相关测试、构建和文档结构检查通过。
